# 方言チャットボット 実装計画

- 作成日：2026-11-02
- 対象の仕様書：[spec.md](spec.md)

---

## 1. 基本方針

- **まずLINEで方言の返事が返ってくる状態を最短で作り、その後で管理画面を広げていく。**
- フェーズごとにブランチを切り、PRを出してから main にマージする。
- 各フェーズの終わりに、本番環境で動作を確認する。

---

## 2. 開発環境と運用ルール

| 項目 | 内容 |
|---|---|
| ブランチ | `phase-<番号>-<名前>`（例：`phase-1-minimal-bot`） |
| PR | フェーズごとに1つ出す。Vercel の Preview 環境で確認してからマージする |
| LINE チャネル | 開発用と本番用の2つ。開発用は ngrok などでローカルか Preview 環境に、本番用は本番URLに向ける |
| DB | Neon の本番用と開発用（Neon のブランチ機能）に分ける |
| パッケージ管理 | pnpm |
| テスト | Vitest で判定の処理の単体テストを書く。LLM と LINE の呼び出しはモックにする。E2E テストは作らない |
| 最初に使う LLM | Gemini（フェーズ1で動作を確認する）。呼び出し部分は最初から3社に対応させる |

## 4. フェーズ

### フェーズ0：土台作り
**ブランチ**：`phase-0-setup`

- Next.js（App Router、TypeScript）の初期設定
- ESLint / Prettier、Vitest の設定
- Drizzle と Neon の接続、マイグレーションの仕組み
- 環境変数の定義と検証（足りないときに起動時に分かるようにする）
- Vercel へのデプロイ

**完了の条件**：空のアプリが本番URLで動き、DB にもつながる。

### フェーズ1：最小のBot
**ブランチ**：`phase-1-minimal-bot`

- テーブル：`chats`、`messages`、`personas`、`persona_versions`、`settings`、`line_users`
- Webhook：署名の検証、200 をすぐ返して後から処理する、`webhookEventId` による重複の除外
- 1対1のトーク：follow / unfollow、テキストメッセージへの返信、ローディング表示
- LLM の呼び出し部分：Vercel AI SDK で3社に対応する、時間切れ、エラー時の定型文
- 会話の記憶：直近N往復分、最大M件
- 返答の記録：ペルソナ版、モデル、トークン数、応答時間
- コマンドを登録する仕組み（中身は空）
- 初期データを入れるスクリプト：最初のペルソナと全体の設定
- 単体テスト：履歴の組み立て、コマンドの判定

**完了の条件**：**開発用と本番用の両方のチャネルで、1対1のトークで方言の会話ができる。**

### フェーズ2：グループ対応
**ブランチ**：`phase-2-group`

- join / leave のイベント、グループ名の取得
- 返信条件：メンション（`isSelf`）／キーワード／すべて。メンションの部分を本文から取り除く
- 発言者の表示名を取得し、キャッシュする
- グループの履歴：話者名を付ける、同じロールが続いたらまとめる、Bot が呼ばれていない発言も含める
- 単体テスト：返信条件の判定、話者名を付けた履歴

**完了の条件**：実験用グループで、メンションしたときだけ方言で返事が来る。

### フェーズ3：管理画面の基盤
**ブランチ**：`phase-3-admin-base`

- テーブル：`admins`
- Auth.js の Google ログイン、許可リストによるログインの制限、`INITIAL_ADMIN_EMAIL` の登録
- 管理画面の枠組み（レイアウト、メニュー）とサーバー側での権限の確認
- 管理者の管理画面（追加と削除）

**完了の条件**：登録した複数の管理者だけがログインできる。

### フェーズ4：ペルソナの調整
**ブランチ**：`phase-4-persona`

- ペルソナの一覧、作成、複製、削除
- ペルソナの編集（保存すると新しい版になる）、版のメモ
- 版の履歴、2つの版の違いの表示、過去の版から新しい版を作る、現行版の切り替え
- プレイグラウンド（保存前の内容でも試せる。DB には保存しない）
- API キーが設定されていないプロバイダーを選べないようにする

**完了の条件**：**方言の調整を管理画面だけで回せる。**

### フェーズ5：設定と制限
**ブランチ**：`phase-5-settings`

- テーブル：`daily_usage`
- チャットの一覧と設定（ペルソナの割り当て、返信条件、キーワード、上書きできる項目）
- 全体の設定の画面
- 回数制限（日本時間で日ごとに数える）、上限時の定型文
- 単体テスト：日本時間の日付の扱い、上限の判定、設定の上書きの決まり方

**完了の条件**：仕様書にある設定をすべて画面から変えられる。

### フェーズ6：評価とログ
**ブランチ**：`phase-6-feedback`

- テーブル：`feedbacks`
- LINE からの評価（引用と 👍 / 👎、コメント、引用しない場合は最後の返答、上書き、受け付けたときの返信）
- 会話ログの閲覧、管理者による評価、削除（1件ずつ／期間を指定／チャットのすべて）
- 評価一覧（絞り込み）、版ごとの集計、ダッシュボード
- 単体テスト：評価メッセージの解析、評価の対象の決め方

**完了の条件**：仕様書の内容がすべてそろう。
