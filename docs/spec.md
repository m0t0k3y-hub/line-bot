## 1. 概要

### 1.1 目的
LLMを使って、指定した方言とキャラクターで会話する LINE Bot を作る。
**「LLMで方言をどこまで再現できるか」を検証すること**がテーマで、プロンプトとモデルを管理画面から調整・比較できることを重視する。

### 1.2 利用者
| 区分 | 説明 |
|---|---|
| LINEユーザー | 友達（数十名）。1対1のトークと実験用グループで Bot と会話する。AIが応答することは全員が承知している |
| 管理者 | 複数人。管理画面でペルソナの調整、設定の変更、ログの確認を行う |

### 1.3 スコープ
**対象とするもの**
- テキストメッセージによる会話（1対1のトーク、グループ）
- ペルソナ（方言＋キャラクター＋モデル）の管理と版の履歴
- 会話の記憶（Bot が呼ばれていない発言を含む）
- 返答の評価（LINEと管理画面の両方から）
- 回数制限
- 管理画面（複数の管理者、Googleアカウントでのログイン）

**対象外（将来の拡張は「11. 将来の拡張」を参照）**
- リッチメニュー
- 画像、スタンプ、音声などテキスト以外のメッセージへの応答
- LINE上からのペルソナ切り替え
- 複数モデルの同時比較
- 会話の記憶のリセット

## 2. 用語

| 用語 | 意味 |
|---|---|
| ペルソナ | 方言とキャラクターの設定、および使うモデルをまとめた単位（例：「博多のおばちゃん」） |
| ペルソナ版 | ペルソナの中身（プロンプト、モデルなど）を保存したもの。保存のたびに新しい版ができ、作った版は変更しない |
| 現行版 | ペルソナが今使っている版 |
| チャット | Bot が参加している会話の場。1対1のトーク（user）、グループ（group）、複数人トーク（room）のいずれか |
| 返信条件 | グループで Bot が返信するかどうかを決める条件（メンション／キーワード／すべて） |
| 往復 | ユーザーの発言とそれに対する Bot の返答の組 |

## 4. LINE Bot の機能

### 4.1 受け付けるイベント
| イベント | 処理 |
|---|---|
| message（text） | 「4.2 メッセージ処理の流れ」のとおり処理する |
| message（text以外） | 何もしない（記録もしない） |
| join（グループ／トークへの参加） | チャットを登録する。グループ名を取得する |
| leave（退出） | チャットを「無効」にする。ログは残す |
| follow / unfollow | 1対1のチャットを登録する／無効にする |
| その他 | 何もしない |

### 4.2 メッセージ処理の流れ
```
1. 署名（x-line-signature）を検証する。失敗したら 401 を返す
2. LINE に 200 を返す（以降の処理は応答の後に非同期で行う。Next.js の after() などを使う）
3. webhookEventId が処理済みなら終了する（LINE の再送で同じイベントが重複するのを防ぐ）
4. チャットを取得する。なければ登録する
5. 送信者の表示名を取得する（キャッシュがなければ LINE API から取り、保存する）
6. 評価メッセージかどうかを判定する（4.6）
     → 評価なら、評価を保存して終了する（LLMは呼ばない。履歴にも含めない）
7. コマンドかどうかを判定する（4.7）
     → コマンドなら、そのコマンドを実行して終了する（初版ではコマンドなし）
8. メッセージを保存する（Bot が返信するかどうかに関係なく、必ず保存する）
9. 返信するかどうかを判定する（4.3）
     → 返信しないなら終了する
10. 回数制限を確認する（4.5）
     → 上限に達していたら、上限時の定型文を Reply して終了する
11. （1対1のトークのみ）ローディング表示を出す
12. 使うペルソナの現行版を決める（4.8）
13. 会話履歴を組み立てる（4.4）
14. LLM を呼び出す（6章）
15. 返答を Reply API で送る
16. 返答を保存する（LINE が返した送信メッセージID、ペルソナ版、モデル、トークン数、応答時間）
17. 当日の回数を 1 増やす
```

**エラー時の扱い**
- LLM の呼び出しに失敗した、または時間切れになったときは、エラー時の定型文を Reply する。返答ログにはエラー内容を記録する。
- エラーになった返答は、回数制限には数えない。

### 4.3 返信条件
| チャットの種類 | 返信条件 |
|---|---|
| 1対1（user） | 常に返信する |
| グループ／複数人トーク | チャットごとの設定 `reply_mode` に従う。標準は `mention` |

| reply_mode | 返信する条件 |
|---|---|
| `mention` | Bot がメンションされたとき（`mention.mentionees` に `isSelf: true` が含まれるとき） |
| `keyword` | 発言が、設定したキーワードのいずれかで始まるとき（キーワードは複数登録できる） |
| `all` | すべての発言 |

- メンションの部分（`@Bot名`）は、LLM に渡す本文から取り除く。

### 4.4 会話の記憶（履歴の組み立て）
- **Bot が呼ばれていない発言も含めて**、チャット内のテキストメッセージをすべて保存する。
- LLM に渡す履歴は、次の範囲とする。
  - **直近 N 往復分**：直近から数えて N 個目の Bot の返答より後にある、すべてのメッセージ（ユーザーの発言と Bot の返答）
  - ただし **最大 M 件** までとする。発言が多いグループで履歴が膨らみすぎるのを防ぐため
- N（`history_turns`）と M（`history_max_messages`）は設定で変えられる（全体の設定、およびチャットごとの上書き）。
  - 初期値：N = 10、M = 50
- 履歴の形式
  - ユーザーの発言は `user`、Bot の返答は `assistant` のロールで渡す。
  - グループでは、誰の発言か分かるように本文の前に表示名を付ける（例：`[たろう] 今日なんしよーと？`）。
  - 同じロールが続く場合は、1つのメッセージにまとめる（プロバイダーの制約に合わせるため）。
- 評価メッセージと、エラーになった返答は履歴に含めない。

### 4.5 回数制限
- **単位**：チャットごと、1日あたり、Bot が返信した回数
- **リセット**：日本時間の 0:00
- **初期値**：100回／日
- 上限に達しているときに返信の条件を満たすと、**上限時の定型文**を Reply する（LLM は呼ばない。この返信は回数に数えない）。
- 上限の回数と定型文は、全体の設定で決め、チャットごとに上書きできる。
  - 定型文の初期値：「今日はもう疲れたけん、また明日ね」

### 4.6 評価（LINE から）
- **評価の送り方**：Bot の返答を**引用（リプライ）して**、次の記号で始まるメッセージを送る。
  - `👍` → 良い（+1）
  - `👎` → 悪い（−1）
  - 記号の後ろの文章はコメントとして保存する（例：`👎 博多ではそげん言わんよ`）
- **評価の対象**
  - 引用されたメッセージ（`quotedMessageId`）が、保存してある Bot の返答の送信メッセージIDと一致すれば、その返答を評価の対象にする。
  - 引用せずに `👍` / `👎` で始まるメッセージを送った場合は、そのチャットで最後に送った Bot の返答を対象にする。
- 評価メッセージは、返信条件（メンションなど）に関係なく受け付ける。
- 評価メッセージは LLM に渡さず、会話履歴にも含めない。
- **受け付けたことの通知**：初期設定では返信しない。全体の設定で、受け付けたときに短い定型文を返すようにもできる。
- 同じ人が同じ返答を再び評価した場合は、新しい評価で上書きする。

### 4.7 コマンド
- `/` で始まるメッセージはコマンドとして扱い、LLM には渡さない。
- **初版で実装するコマンドはない。** 登録されていないコマンドは何もしない（記録もしない）。
- コマンドの名前と処理を登録するだけで追加できる作りにする（将来、`/reset` などを追加するため）。

### 4.8 使うペルソナの決め方
1. チャットに個別のペルソナが割り当てられていれば、そのペルソナを使う。
2. 割り当てがなければ、全体の設定の標準ペルソナを使う。
3. どちらもなければ返信しない（ログに警告を残す）。

使うのは、そのペルソナの**現行版**とする。

### 4.9 LINE の制約への対応
| 制約 | 対応 |
|---|---|
| Push メッセージは無料プランで月200通まで | 返信はすべて Reply API で行う。Push は使わない |
| Reply トークンには有効期限がある | 受信後すぐに処理を始める。LLM の呼び出しは時間切れ（初期値30秒）を設ける |
| テキストは1通あたり最大5,000文字 | 超えた分は切り捨てる（方言の会話でここまで長くなることは想定していない） |
| ローディング表示は1対1のトークだけで使える | グループでは表示しない |
| Webhook は再送されることがある | `webhookEventId` で重複を除く |

## 5. 管理画面

### 5.1 認証
- Auth.js の Google ログインを使う。
- `admins` テーブルに登録されたメールアドレスの人だけがログインできる。登録されていない人はログインを拒否する。
- 最初の管理者は環境変数 `INITIAL_ADMIN_EMAIL` で指定する（起動時に `admins` に登録されていなければ追加する）。
- 管理者の間に権限の差は設けない（全員が全機能を使える）。

### 5.2 画面一覧
| # | 画面 | パス（案） | 主な機能 |
|---|---|---|---|
| 1 | ログイン | `/admin/login` | Googleアカウントでログインする |
| 2 | ダッシュボード | `/admin` | 今日の返信数（チャット別）、最近の評価、エラーの件数 |
| 3 | ペルソナ一覧 | `/admin/personas` | 一覧、新規作成、複製、削除（使用中のペルソナは削除できない。削除は一覧から隠すアーカイブ方式） |
| 4 | ペルソナ編集 | `/admin/personas/[id]` | 現行版の編集と保存（保存すると新しい版になる）、プレイグラウンドへの移動 |
| 5 | 版の履歴 | `/admin/personas/[id]/versions` | 版の一覧（メモ、作成者、日時）、版ごとの評価の集計、2つの版の違いの表示、現行版の切り替え、過去の版から新しい版を作る |
| 6 | プレイグラウンド | `/admin/playground` | ペルソナと版（または保存前の編集内容）を選んで、管理画面上で会話を試す |
| 7 | チャット一覧 | `/admin/chats` | Bot が参加しているトーク・グループの一覧（種類、名前、今日の回数、有効／無効） |
| 8 | チャットの設定 | `/admin/chats/[id]` | ペルソナの割り当て、返信条件、キーワード、何往復分を記憶するか、回数の上限と上限時の定型文の上書き |
| 9 | 会話ログ | `/admin/chats/[id]/messages` | 時系列のログ（Bot の返答にはペルソナ版、モデル、トークン数を表示）、管理者による評価、削除 |
| 10 | 評価一覧 | `/admin/feedbacks` | すべての評価の一覧。ペルソナ、版、モデル、良い／悪いで絞り込める。コメントの確認に使う |
| 11 | 全体の設定 | `/admin/settings` | 標準ペルソナ、記憶の往復数、履歴の最大件数、回数の上限、各定型文、評価を受け付けたときに返信するか |
| 12 | 管理者の管理 | `/admin/admins` | 管理者の追加と削除（自分自身は削除できない） |

### 5.3 ペルソナ編集の項目
| 項目 | 内容 |
|---|---|
| 名前 | 一覧に表示する名前 |
| 説明 | 管理者向けのメモ（LLM には渡さない） |
| システムプロンプト | 方言のルール、キャラクター設定（年齢、性格、一人称など）、話し方の指示。自由に書ける |
| 会話例（few-shot） | 「ユーザーの発言」と「理想の返答」の組を複数登録できる。LLM には会話履歴の前に、過去のやり取りとして渡す |
| プロバイダー | `anthropic` / `openai` / `google` |
| モデルID | 自由に入力できる。よく使うモデルは候補として表示する（新しいモデルにすぐ対応できるようにするため） |
| 最大出力トークン数 | 共通の項目 |
| プロバイダー別のオプション | 上級者向け。JSON で自由に指定する（例：effort、temperature）。モデルによって使える項目が違うため、自由入力とする |
| 版のメモ | 保存するときに任意で入力する（例：「語尾の『〜けん』を増やした」） |

### 5.4 プロンプトの履歴
- 保存するたびに `persona_versions` に新しい行を追加し、その版を現行版にする。
- 作った版は変更・削除しない。
- 過去の版に戻すときは、その版の内容をコピーした新しい版を作り、現行版にする。
- 2つの版の違いは、システムプロンプト、会話例、モデルの設定ごとに、行単位で色分けして表示する。

### 5.5 プレイグラウンド
- ペルソナと版を選ぶ。またはペルソナ編集画面から、保存前の内容をそのまま試せる。
- 会話は画面上だけで行い、DB には保存しない（本番のログや評価の集計に混ぜないため）。
- 返答ごとに、モデル、トークン数、応答時間を表示する。
- 会話をクリアするボタンを置く。

### 5.6 評価の集計
- 版の履歴の画面で、版ごとに次の値を表示する：返答の数、👍の数、👎の数、👍の割合。
- 評価一覧の画面で、モデルやペルソナごとに絞り込める。
- 管理者が会話ログから付けた評価も集計に含める（評価の出どころ：`line` / `admin`）。

### 5.7 ログの削除
- 会話ログの画面から、次の単位で削除できる。
  - メッセージを1件ずつ
  - 期間を指定して（チャット単位）
  - チャットのすべてのログ
- 削除したメッセージに付いていた評価も一緒に削除する（評価の集計からも消えることを、確認ダイアログで伝える）。
- 自動では削除しない。

## 6. LLM の呼び出し

### 6.1 プロバイダーの切り替え
- Vercel AI SDK を使い、ペルソナ版に記録されたプロバイダーとモデルIDでモデルを選ぶ。
- 対応するプロバイダー：Anthropic（Claude）、OpenAI、Google（Gemini）
- APIキーは環境変数で設定する。キーが設定されていないプロバイダーは、管理画面で選べないようにする。

### 6.2 LLM に渡す内容
```
system   : ペルソナ版のシステムプロンプト
           ＋ 状況の補足（例：「ここはグループ『〇〇』での会話です。発言の前の[名前]は話者を表します」）
messages : 会話例（few-shot）
           ＋ 会話履歴（4.4）
           ＋ 今回の発言
```
- 状況の補足は、システムが自動で付ける。文面は実装時に決める。

### 6.3 記録する項目
返答ごとに、次の項目を保存する。
- ペルソナ版のID、プロバイダー、モデルID
- 入力と出力のトークン数（プロバイダーが返す値）
- 応答時間（ミリ秒）
- エラー（失敗したとき）

## 8. 非機能要件

### 8.1 セキュリティ
- LINE の Webhook は、署名を必ず検証する。
- API キーやチャネルシークレットは、Vercel の環境変数にだけ置く。DB やコードには書かない。
- 管理画面とその API はすべて認証を必須にする。管理画面の API は、サーバー側でも管理者かどうかを確認する。
- ユーザーの発言を LLM に送ることは、利用者全員が承知している（実験用グループのため）。

### 8.2 性能と可用性
- Webhook には、検証の後すぐに 200 を返す。重い処理は応答の後に行う。
- Vercel Functions の最大実行時間（maxDuration）は、LLM の時間切れより長く設定する（例：60秒）。
- 規模は数十名、1チャットあたり1日100回程度。それ以上の拡張性は考えない。

### 8.3 運用
- ログは手動で削除する（自動では削除しない）。
- トークン数を記録しておき、モデルごとの使用量を後から確認できるようにする。
